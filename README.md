# QRコード媒介型データ送受信アプリ

災害時やオフライン環境における高速データ伝送を検証するためのAndroidアプリケーションです。汎用スマートフォンのディスプレイとカメラを用いた「スクリーン・カメラ通信」を実装し、最大30fpsでの安定したデータ送受信とエラー率の検証を目的として開発しました。

本プロダクトを用いた実証実験の成果は、情報処理学会にて論文として公開されています。

 **論文リンク**: https://ipsj.ixsq.nii.ac.jp/records/2007423

## 主な機能と技術的な工夫

本アプリは、送信側（最大30fps）と受信側の双方で、極限まで処理遅延をなくすための最適化を行っています。

### 1. 送信処理の高速化（100ms → 10ms）
1秒間に30フレーム（33ms以内/フレーム）での高速送信を実現するため、以下の最適化を実装しました。
* **スレッドの分離**: QRコードの「生成」と「表示」のプロセスを別スレッドに分離。
* **描画ロジックの軽量化**: 全ピクセルを順次描画する方式を廃止し、1モジュール＝1ピクセルで軽量描画した後に一括でスケーリング（拡大）する方式を採用。
* **データ構造とアルゴリズムの最適化**: QRコードに格納するバイナリデータの最大サイズ取得処理を、二分探索から、配列による定数時間のルックアップ方式へ変更し計算量を削減。

  
### 2. 実運用を想定したエラー耐性とロギング
実験データを正確に収集するため、アプリ内に堅牢なロギング機構を実装しています。
* **非同期CSV出力 (`CsvWorker.java`)**: メインスレッドのUI描画を阻害しないよう、`BlockingDeque` を用いた別スレッドでのログ書き込みを実装。
* **ファイルローテーション**: 長時間の実験に耐えうるよう、ログファイルが肥大化した際の自動バックアップ機能を組み込んでいます。

### 3. 2段階デコード（Early Exit）によるCPU負荷削減と認識率の両立
毎フレーム高解像度（1080x1080）の全体画像をデコード対象にすると、画像処理の計算負荷が非常に高くなり、端末の熱暴走やフレームドロップ（BUSY_DROP）、デコードのタイムアウトが発生するという課題がありました。この課題を解決するため、以下の「2段階デコードパイプライン」を自作・実装しました。

1. **Stage 1（中央局所スキャン）**
   ユーザーがQRコードを画面中央に捉える特性を活かし、画面中央のエリア(例：400x400 px ）のみをクロップして先行デコードします。画像サイズを小さく絞ったことで、高速での処理を実現しました。ここで成功した場合は、即座に次のフレームの処理へ移行（Early Exit）します。
2. **Stage 2（全体フォールバック）**
   手ブレや移動によってQRコードが中央から外れ、Stage 1で失敗した場合のみ、1080x1080の全体画像をデコードします。

## 既知の課題
実機でのテストやログの確認を行う中で、現在のプロトタイプ実装においていくつか修正すべき挙動や潜在的なリスクを見つけたため、今後のリファクタリング対象として記録しています。

### 1. **高負荷時におけるフレームドロップ（`busy_drop`）の発生と要因分析**
  * 実機での実験中、高フレームレート（30fps）環境においてフレームが解析されずに破棄される挙動（ログ上の `busy_drop`）を確認しました。
  * 直接的な原因は、**「次のフレームの到着間隔（約33ms）」が「1フレームあたりのデコード時間」を下回ってしまったこと**です。
  * デコード時間が長期化した根本原因は調査中ですが、デコード用の固定スレッドプール（3スレッド）を親タスクと子タスク（Stage1/Stage2）で共有しているため、スレッドが一時的に枯渇し、処理のブロッキングが発生した可能性が高いと考えています。
  * 今後は、タスクごとにExecutorを分離し、キューが詰まらないアーキテクチャに改善予定です。

### 2. **端末間の時刻同期について**
  * 本システムでは、QRコード表示側（送信端末）とデコード側（受信端末）の間で、NTP等によるミリ秒単位の厳密な時刻同期を行っていません。
  * そのため、ログデータのうち端末間を跨ぐ時間差（`prod-sensor_ms` や `prod-decode_ms` など）は、各端末の内部時計のズレの影響を受けるため、正確な値にならない（または `-1` となる）場合があります。

### 3. **先行開発時の実験コードの残存と今後のリファクタリング**
  - 開発初期、さらなる高速化のために「デコード前に画像のシャープネスや照度、ピクセル数を計測し、低品質なフレームを即座に弾く事前フィルタリング機能」を検討・試作しました。
  - しかし実機検証の結果、「環境光やカメラ性能による個体差が激しく閾値設定が困難なこと」「品質計測自体の計算負荷が重く、本末転倒になること」の2点から不採用としました。
  - 現在、ログのカラム（照度等）やコードの一部にその名残が残っていますが、アプリの動作（10ms前後のデコード）には影響ありません。これらは今後、削除・整理予定です。

## ローカルでのビルド方法

1. 本リポジトリをクローンします。
   ```bash
   git clone https://github.com/hidehito-kawashima/qr-code-communication-app.git
2. Android Studioを起動し、 `Open` からクローンしたフォルダ内の **`MyApplication`** フォルダを選択して開いてください。
   （※一番外側のルートフォルダを開くと、Gradleが正しく認識されない場合があります）
3. Gradle Syncを実行します。
4. 実機端末（Android）を接続し、実行（Run）してください。

 ## **実機で動作確認・実験をされる際のお願い**
  * 本アプリは学術研究でのデータ収集に特化して開発したプロトタイプのため、一般的な商用アプリのような多様な端末環境での網羅的な動作検証（安全性能テスト）は行っておりません。
  * 最大30fpsでの画像解析や高頻度なログ書き込みなど、スマートフォンのリソースを限界まで使用する設計になっているため、実行中に端末が発熱したり、一時的に挙動が重くなったりする可能性があります。
  * もし実機にインストールして動作を確認される場合は、端末への負荷や予期せぬ挙動を避けるため、ご自身のテスト用端末等をご使用いただき、検証後はアプリを終了していただくなど、お取り扱いにご注意いただけますと幸いです。
